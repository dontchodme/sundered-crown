## Why tools/ has no subfolders

Every tool resolves the game by looking *beside itself* (`HERE = Path(__file__).parent`)
and imports `scpage.py` the same way. Splitting them into `build/ check/ render/`
would break every one of them, and it would break them *silently* — the import
fails only when you run it. That is a worse trade than a long directory, so the
grouping lives in `tools/README.md` instead, which lists all 62 by purpose.

## To rebuild the artifact from scratch

Run inside `tools/`, with the chain's HTML beside the tools:

```
cp ../02-chain/sc-base.html .
python3 roster15_build.py   --src sc-base.html       --out sc-c1.html
python3 cinema_build.py     --in  sc-c1.html         --out sc-c2.html
python3 wallglow_build.py   --src sc-c2.html         --out sc-all.html
python3 introcard_build.py  --src sc-all.html        --out sc-everything.html
python3 roster_gs_build.py  --src sc-everything.html --out sc-gs7.html
python3 ultart_build.py     --src sc-gs7.html        --out sc-gs7-ults.html
python3 ultart2_build.py    --src sc-gs7-ults.html   --out sc-ults-all.html
```

`sc-ults-all.html` must come out `ba423d8e6453592d`. That file, copied to
`sundered-crown.html`, is the artifact.

**Do not build from `sundered-crown.html`.** It is the chain's OUTPUT now.
Feeding it back in would double-apply every builder.

## Where the numbers live

Tuned damage is held by the **builders**, never by the HTML:

* the twelve original relics → `roster15_build.py`, the `TUNED` dict
* the four new greatswords → `roster_gs_build.py`, `TUNED_GS`
* status and ultimate wording → `introcard_build.py`, the tip-edit list

`tune.py --apply` refuses to write into anything carrying a `GENERATED by`
stamp, which is every file in `02-chain/`. This is not fussiness: a previous
session wrote twelve converged damage values straight into `sc-r15.html` and
lost all twelve on the next rebuild.
