# REPRODUCING THE BUILD OF RECORD

**Written 2026-08-28, after the renderer work put four new links on the chain
and nothing wrote down the order.**

`02-chain/sc-paradox-fx.html` is the build of record. It is the output of a
chain of builders, each one splicing into the previous one's HTML. Every file
in `02-chain/` carries a `GENERATED by` stamp and **must not be hand-edited** —
a previous session wrote twelve tuned damage values into generated HTML and
lost all twelve on the next rebuild.

---

## 1. THE STAMPS ARE THE RECIPE. READ THEM BOTTOM TO TOP.

Each builder prepends its own line, so the head of any chain file is its own
build history, newest first:

```bash
head -14 02-chain/sc-paradox-fx.html
```

```
GENERATED by post_build.py       --src sc-paradox-dawn.html
GENERATED by ultcarry_build.py   --src sc-paradox-readouts.html
GENERATED by readouts_build.py   --src sc-paradox-cine.html
GENERATED by cineexport_build.py --src sc-paradox.html
GENERATED by introcard_build.py
GENERATED by ultdawn_build.py    --src sc-crucible.html
GENERATED by ultforge_build.py   --src sc-ults-all.html
GENERATED by ultart2_build.py    --src sc-gs7-ults.html
GENERATED by ultart_build.py     --src sc-gs7.html
GENERATED by roster_gs_build.py  --src sc-everything.html
GENERATED by wallglow_build.py   --mode buf --down 4 --src sc-c2.html
GENERATED by roster15_build.py
```

**This is the authoritative record and it cannot go stale**, because a builder
that runs writes its own line. Any prose recipe — including the one below —
can drift from it. When they disagree, the stamps are right.

## 2. THE FOUR NEW LINKS, WITH EXACT ARGUMENTS

Everything above `introcard_build.py` was the v43 tip and is unchanged. The
renderer work added four links on top of `sc-paradox.html`:

```bash
cd tools

python cineexport_build.py --src ../02-chain/sc-paradox.html \
                           --out ../02-chain/sc-paradox-cine.html

python readouts_build.py   --src ../02-chain/sc-paradox-cine.html \
                           --out ../02-chain/sc-paradox-readouts.html

python ultcarry_build.py   --src ../02-chain/sc-paradox-readouts.html \
                           --out ../02-chain/sc-paradox-dawn.html

python post_build.py       --src ../02-chain/sc-paradox-dawn.html \
                           --out ../02-chain/sc-paradox-frame.html
```

| link | what it adds |
|---|---|
| `cineexport_build.py` | exports `CINE` so the post chain can read the director's tier and ramp the effects with the cut instead of applying them flatly |
| `readouts_build.py` | splits floats, tags and HUD into their own layer, so bloom reaches the fight and not the numbers |
| `ultcarry_build.py` | carries corrected ult set-pieces to the tip when their owning builder cannot be replayed — Daybreak's corona, Benediction, the Harrowing |
| `post_build.py` | inserts `src/render/post.js`. Bloom ON; trails and grade present and default OFF |
| `fx_build.py` | inserts `src/render/fx.js` — the particle fields, 25 specs over 6 emitter modes. One hook, at the end of `drawUltOver`, which is the layer `readouts_build.py` split out for the bloom |

## 3. THE TRAP — CLOSED, AND THIS SECTION WAS STALE

> **`post_build.py` run with no arguments DOES rebuild the tip.** Verified
> 2026-08-28: a bare run into a scratch path is **byte-identical** to
> `02-chain/sc-paradox-fx.html`.

All four builders' defaults are now correct — `cineexport_build.py`,
`readouts_build.py`, `ultcarry_build.py` and `post_build.py` each default to
exactly the link they made:

```python
ap.add_argument("--src", default="../02-chain/sc-paradox-dawn.html")
ap.add_argument("--out", default="../02-chain/sc-paradox-frame.html")
```

**What the trap WAS**, kept because it is the clearest example of §4.10 in the
repo: `post_build.py`'s defaults were left over from the session before
`ultcarry_build.py` existed, so a bare run read `sc-paradox-readouts.html`,
skipped `ultcarry_build.py` entirely, and wrote `sc-paradox-post.html` — a
build with none of the ult art fixes, under a filename that is not the build of
record, with nothing erroring. `02-chain/sc-paradox-post.html` on disk is that
superseded output and is not on the current chain.

Fixed in `c743897`. **And this document went on describing it as live for
several sessions afterward** — long enough that
`docs/FX-RUNTIME-BRIEF.md`'s Stage 0, written off `46e37edc`, listed it as the
first debt to clear. `c743897` is an ancestor of that commit. A doc that
describes a closed trap costs the same as one that hides an open one: the next
session spends its first half hour on work that is already done.

This is §4.10 wearing a different hat: **a builder whose default points at the
wrong link will happily produce a wrong build and say nothing.** Pass `--src`
and `--out` explicitly, every time.

**The real fix is two strings** — `post_build.py` should default to
`sc-paradox-dawn.html` → `sc-paradox-frame.html`. It was left undone rather
than changed blind, because in this repo a builder change is followed by
`chain_audit.py` and `engine_ab.py` against the machine that owns the chain,
and an edit made without those is the thing §4.10 is warning about. Change it
and run them.

## 4. AFTER ANY REBUILD

```bash
cd tools
python chain_audit.py --relic ../02-chain/sc-paradox.html \
                      --tip   ../02-chain/sc-paradox-fx.html \
                      --builder post_build.py     # inserts survive to the tip
python post_identity.py                            # the chain is invisible to the sim
python engine_ab.py --a <the previous tip> --b ../02-chain/sc-paradox-fx.html \
                    --ids <all 25> --n 10          # nothing moved
python verify.py --game ../02-chain/sc-paradox-fx.html --n 40
```

`chain_audit.py` **defaults to `twinshade_build.py`** and will audit the wrong
inserts and pass. Always pass `--builder`.

An independent A/B of the whole renderer arc — the v43 tip against this one,
both arms in a single runtime — came back **192/192 fights identical**. That is
the number a rebuild has to keep.

---

## 5. THE RULE

**A new chain link updates three things in the same session, or it is not
done:** the builder's own `--src` / `--out` defaults, §2 of this file, and
`tools/README.md`'s BUILD list. The stamps take care of themselves; the prose
does not.
